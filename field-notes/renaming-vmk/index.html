Renaming vmk Adapter

Did you know that you can rename VMK adapters on an ESX host relatively easily? Did you know that you can rename VMK adapters on an ESX host relatively easily?

Preparation

The ESX host should be in maintenance mode, and a reboot is required to apply the settings. In addition, SSH must be temporarily enabled on the host. You can use esxcfg-vmknic -l to display all vmk adapters on the ESX host.

Execution

First, we export the current configuration of the vmk adapters to a JSON file so we can edit it manually. Then we overwrite the existing configuration with our changes and reboot the system. The changes will then be persistent.

configstorecli config current get -c esx -g network -k vmknics > vmknics.json

vi vmknics.json

configstorecli config current set -c esx -g network -k vmknics -j vmknics.json --overwrite

reboot now

Why?

Well, the answer is relatively simple: to simplify operation and troubleshooting. When you build a VCF cluster with different network configurations (different server generations or more network cards), it can be confusing when you try to troubleshoot something in the logs and find that the vMotion VMK adapter is adapter 2 on one server and adapter 3 on another. Another example is Host Add in a VxRail VCF cluster. With VCF 9.1, the VxRail host loses its VMK 0 discovery interface after host commissioning. As a result, the VMK assignment no longer matches that of the existing host. This isn’t really a problem, but having identical VMK names makes operations easier.

A quick warning to wrap things up
Do not use this method to change the names of the NSX vmk adapters!
